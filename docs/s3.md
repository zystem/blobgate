# Use the S3 door

How-to page. The S3 door lets the tools that speak S3 (the AWS CLI, `s3cmd`, `rclone`, the SDKs) read and write the objects of a tenant. What it answers and what it does not: [s3-reference.md](s3-reference.md).

You need a running module with a store ([../README.md](../README.md)) and the secret of a tenant (`BLOBGATE_TENANTS`).

1. Turn the door on with a port (it is off by default). In the environment of the module:

   ```bash
   BLOBGATE_S3_PORT=18093
   ```

   The module says nothing more at start; the door answers on that port at once. Serve it over TLS like the other ports (`BLOBGATE_TLS_CERT_FILE`) when it leaves the cluster: the signature protects a call, not the bytes.

2. Make the key pair of the tenant. The access key is the name of the tenant; the secret key is made from the tenant's secret, and is not that secret:

   ```bash
   blobgate s3-key acme the-secret-of-acme
   ```

   ```text
   access key: acme
   secret key: 1d0c...e5a2
   ```

   (The secret key is 64 hexadecimal characters; it is cut here.)

3. Point the tool at the door. The bucket is the name of a **store** (the operator makes the stores; a tool cannot make a bucket). Use path-style addresses (`http://host:18093/bucket/key`), which is what an address with a port gives.

   The AWS CLI:

   ```bash
   export AWS_ACCESS_KEY_ID=acme AWS_SECRET_ACCESS_KEY=1d0c...e5a2 AWS_DEFAULT_REGION=us-east-1
   aws --endpoint-url http://127.0.0.1:18093 s3 cp big.bin s3://media/docs/big.bin
   aws --endpoint-url http://127.0.0.1:18093 s3 ls s3://media/docs/
   aws --endpoint-url http://127.0.0.1:18093 s3 sync s3://media/docs/ ./docs
   ```

   ```text
   upload: ./big.bin to s3://media/docs/big.bin
   2026-11-14 02:43:11   30000000 big.bin
   download: s3://media/docs/big.bin to docs/big.bin
   ```

   `s3cmd` (a file `s3cfg` with `access_key`, `secret_key`, `host_base = 127.0.0.1:18093`, `host_bucket = 127.0.0.1:18093`, `use_https = False`); its multipart size must be 8 MiB or less:

   ```bash
   s3cmd -c s3cfg --multipart-chunk-size-mb=8 put big.bin s3://media/s3cmd/big.bin
   ```

   ```text
   upload: 'big.bin' -> 's3://media/s3cmd/big.bin' (30000000 bytes in 0.3 seconds, 111.62 MB/s) [1 of 1]
   ```

4. Set the size of a part to 8 MiB or less when the tool sends big objects in parts. A part larger than 8 MiB is refused with the words that say what to set (`a part is at most 8388608 bytes (8 MiB); set the size of the parts of the tool to 8 MiB or less`).

   * AWS CLI: its default (8 MB) works; `aws configure set default.s3.multipart_chunksize 8MB` states it
   * SDK for Go (`manager.Uploader`): `PartSize` of 8 MiB or less (its default, 5 MiB, works)
   * `s3cmd`: `--multipart-chunk-size-mb=8` (its default, 15, is refused)
   * the MinIO client `mc`: `mc put --part-size 8MiB` (its default, 16 MiB, is refused); `mc cp --disable-multipart` sends one request
   * `rclone`: its default (5 MiB) works, and it sends an object under 200 MiB in one request; for a bigger one keep `--s3-chunk-size` at 8M or less

An address that is signed in advance (`aws s3 presign`) works for reads and writes for as long as it says. A call whose signature does not match is refused with `SignatureDoesNotMatch`: the usual causes are a wrong secret key (use the one `s3-key` prints, not the secret of the tenant), a clock more than 15 minutes off,
and an address that is not path-style.

What was run, on 2026-11-14, on one machine, nodes on a local disk: the AWS CLI 1.45 (`cp` of a file of 1 byte and one of 30 MB, which it sends in parts of 8 MiB; `ls`; `sync` in both directions; `rm`; `mb`, which is refused),
the MinIO client `mc` RELEASE.2025-08-13 (`alias set`, `ls`, `cp` and `cat` of a small file, `put --part-size 8MiB` of 30 MB, `cp` back, `cp --disable-multipart`, `stat`, `mirror`, `find`, `rm --recursive`; its default part of 16 MiB is refused as said), `rclone` v1.60.1 (a bucket with `provider = Other` and `force_path_style = true`: `lsd`, `copy` of 1 byte and of 30 MB, `ls`, `copy` back and `cmp`, `check`, which compares the MD5 and found 2 matching files, `copyto`, `sync`, `delete`, `purge`, and a file of 220 MB, which it sends in 5 MiB parts, written, read back identical and deleted), `s3cmd` 2.4.0 (`put` of a small file and, with the 8 MiB option, of 30 MB; `get`; `ls`; `del`), and the SDK for Go of AWS (the tests in `internal/api/s3_test.go`). Not run: the SDKs for other languages,
TLS on the door, a store of FTP, WebDAV or S3 nodes behind it.
